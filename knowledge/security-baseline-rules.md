# 主机安全基线巡检 — 知识规则集

本文件定义 Agent 在巡检与评估时遵循的知识规则与基线标准，并沉淀了来自**真实巡检执行**的实操经验（如 2026-09-06 容器沙箱一轮巡检的判定过程，见 `runs/baseline_report.txt`）。Agent 据此对 `security_baseline_check.sh` 采集到的**客观事实**进行风险评估与整改建议输出。

> 设计原则：**先讲"这条检查会怎么坑你"（失效判据），再给基线值**。规则不是考试填空题，而是让 Agent 少误判、能落地。

---

## 0. 检查项"失效判据"速查（实操优先级最高）

每项检查在真实环境里**最常踩的坑**，判定前先对号入座，避免把"采集失败/工具缺失"误判成"合规"或"高危"：

| 检查项 | 常见误判 | 正确做法 |
|---|---|---|
| SSH 策略 | grep 不到就报高/合规 | `grep` 无命中**不代表合规**，先复核 sshd 是否安装、是否监听 22（真实巡检即发现该沙箱压根没装 SSH，攻击面为 0，判**低风险**而非照搬合规值） |
| 防火墙 | 只查 ufw | ufw 缺失须**并行复核** iptables / nftables / firewalld 是否任一存在；全缺才判"裸奔高风险"。且要说明风险**语境**（接不接公网、是否仅容器内网暴露），不能脱离部署场景一刀切 |
| 口令老化 | 只看 /etc/login.defs | **login.defs 只影响新账户**，必须对现有账户跑 `chage -M 90 -m 7 -W 14 <user>` 才真正生效；仅改 login.defs 属"改了但没落地" |
| 端口 | `ss`/`netstat` 输出为空就当"无监听" | 空**可能是工具未安装**（真实巡检即如此）。须用 `/proc/net/tcp` `/proc/net/udp` 兜底复核后再下结论 |
| SUID | 有 setuid 文件就报高危 | 先区分**包管理器管理的标准程序**（su/passwd/mount 属主 root:root）与**世界可写(/0002)+setuid(/6000) 提权面**；真实巡检发现 8 个标准 SUID 均 root:root 无 world-write，判**低风险** |
| 关键文件权限 | 只比对权限位 | 除 shadow 640 root:shadow 外，需关注 `/etc/crontab`、`/etc/cron.d` 是否被篡改/放开（真实巡检 cron 目录 644 root:root 合规） |

## 1. 职责分工（重要）

- **确定性采集**：一律由 `scripts/security_baseline_check.sh`（纯 bash）完成，结果客观、可复现。
- **拟合判断**：仅 LLM 基于采集事实输出风险等级与整改建议。
- **Agent 不得修改任何系统配置**，只读巡检。
- **采集缺工具时的降级原则**：脚本工具（ss/netstat/ufw）不可用时，Agent 用 `/proc/net`、`find / -perm /6000` 等只读手段兜底复核，**不得因工具缺失直接跳过或臆断**（这是本轮真实巡检中验证过的关键纪律）。

## 2. SSH 加固基线

| 项 | 合规值 | 说明 |
|---|---|---|
| PermitRootLogin | `no` | 禁止 root 远程登录 |
| PasswordAuthentication | `no` | 禁用口令认证，仅密钥 |
| PermitEmptyPasswords | `no` | 禁用空口令 |
| PubkeyAuthentication | `yes` | 启用公钥认证 |

**实操判据**：
- 策略配置落盘后须 `sshd -T | grep -Ei 'permitrootlogin|passwordauthentication'` 复核**生效值**，不能只看配置文件（含 `Include`/`/etc/ssh/sshd_config.d/` 覆盖时文件值与生效值可能不一致）。
- 若本机无 SSH 服务/无监听 22（真实巡检即如此），攻击面为 0，应判**低风险**并说明前提，而非机械套合规值报警。

## 3. 防火墙基线

- 主机应安装管理工具（ufw / nftables / iptables / firewalld 任一），默认入站 `policy drop`，仅放行必要端口与回环流量。
- **任一无防火墙管理工具 → 须复核其余是否全缺**，全缺且主机接入外部网络/端口被映射暴露时判**高风险（裸奔）**。
- 判高风险时必须附带语境：网关层/容器网络是否已有隔离，避免脱离部署拓扑夸大风险。

## 4. 口令老化策略（/etc/login.defs + chage）

| 项 | 合规值 |
|---|---|
| PASS_MAX_DAYS | ≤ 90 |
| PASS_MIN_DAYS | ≥ 1 |
| PASS_WARN_AGE | ≥ 7 |

**实操判据（真实巡检实证）**：
- `PASS_MAX_DAYS=99999` 判**高风险**（永不过期，弱口令风险长期累积）。
- `PASS_MIN_DAYS=0` 判**中风险**（可立即反复改口令，削弱轮换有效性）——比 MAX 收敛，单独列出，不合并成一个大类。
- `PASS_WARN_AGE` 达标（如 7）判**低风险**，不必过度扣分。
- **最关键**：login.defs 仅作用于**新账户**，须对现有账户执行 `chage -M 90 -m 7 -W 14 <user>` 才算落地；整改建议里必须带出这条差异，否则就是"纸上整改"。

## 5. SUID/SGID

**实操判据（真实巡检实证）**：
1. 先区分两类：
   - **标准集**：包管理器管理的系统程序（su、passwd、mount、chfn、gpasswd、chsh、umount、newgrp…），属主 root:root，非 world-writable → 低风险。
   - **提权面**：`find / -xdev -type f -perm /6000` 中同时属主非 root、或 `world-writable(/0002)+setuid/setgid(/6000)` 的 → 高风险。
2. 判定命令建议用 `find / -xdev -type f -perm /6000 -ls` 复核属主，而非只数个数。
3. 出现自研/非常规 SUID → 可疑，报中以上并建议人工核查来源。

## 6. 监听端口

**实操判据（真实巡检实证）**：
- `0.0.0.0`/`::` 对外开放监听 → **高风险暴露面**。
- `127.x.x.x` 回环内部监听（含容器 DNS 类 `127.0.0.11`）→ 低风险，属于常见/必要服务。
- 端口判定前先确认采集工具可用，`ss`/`netstat` 缺失时用 `/proc/net/tcp`,`/proc/net/udp` 兜底（沙箱内只听 127.0.0.11 即由此确认，判低风险）。

## 7. 关键文件权限

| 文件 | 合规 |
|---|---|
| /etc/passwd | 644 root:root |
| /etc/shadow | 640 root:shadow（或更严 600），拒绝普通用户可读 |
| /etc/group | 644 root:root |
| /etc/crontab, /etc/cron.d | 644 root:root，防止被篡改植入定时任务 |

## 8. 执行身份与环境备注

- 巡检以 root 运行时单独注明"环境备注"，**归为低风险/非本机缺陷**，同时建议巡检代理最小权限化（专用只读账户/能力），降低被利用时的提权影响面——这是本期真实巡检的关键经验：**报告要区分"宿主机配置缺陷"与"巡检环境选择"**，不为环境担责、也不隐瞒使用 root。

## 9. 输出规范

- 每个发现输出四项：`事实` + `风险等级(高/中/低)` + `整改建议` + （如适用）`落地命令`。
- 风险分级要**带判据和语境**，能一段话说清"为什么是这个等级"，而不是只给一个标签。
- 只读巡检，末尾声明"未对任何系统配置做出修改"。
